Live recording TUI (deferred)

- Build the TUI after the versioned `.smr` writer and reader/report path are
  stable; the recording file remains the source of truth.
- Feed the live view only cheap aggregate counters (rate, received, Mold gaps,
  writer health, and per-lane backlog), never a copy of every event.
- Refresh at a human-scale rate so terminal rendering cannot delay lane
  consumers or the recording writer.
- Reuse the same decoding and statistics layer for live and offline views.

Postponed: Standard trace-format export

- Keep `.smr` as Samurai's only recording format for now.
- Revisit offline CTF 2 export and Babeltrace interoperability after the
  native recording and analysis workflow is mature.

Postponed: Bare-metal production-topology validation

- Repeat the documented Aya-versus-Mold production-topology benchmark on a
  non-virtualized host with one isolated physical core per Mold consumer.
- Disable or avoid SMT, fix CPU frequency, move IRQs away, prefault memory, and
  record NUMA placement before making an HFT tail-latency claim.
- Extend latency reporting to p99.9 and p99.99 and run long enough for those
  percentiles to contain meaningful sample counts.
- Profile the dedicated `consume_lane` loop and test adaptive empty-lane
  backoff only if it improves CPU cost without regressing p99 latency.

Postponed: RelativeDataLoc live compatibility validation

- The Asahi kernel currently exposes zero `__rel_loc` tracepoint fields, so
  the existing parser and capture-plan support cannot be exercised against a
  naturally available event on this machine.
- Add a synthetic verifier fixture containing relative dynamic data.
- Validate the complete path: relative locator decoding, bounded offset and
  length calculation, generic BPF capture, Mold delivery, and userspace
  decoding.
- Keep the existing unit coverage, and complete this fixture before claiming
  full generic tracepoint compatibility or publishing a release.

Postponed: Mold concurrency verification and fuzzing

- Build one hostile end-to-end correctness test before production release.
- Use the real BPF -> mmap -> userspace path with tiny Mold lanes so producers
  overwrite slots continuously.
- Encode the generation and a generation-dependent pattern in every payload
  word, randomly pause the consumer during copying, and assert that no torn or
  duplicated record is accepted.
- Verify per-lane ordering and exact accounting: received + reported gaps must
  equal produced across wraparound and shutdown draining.
- Run the test for an extended period on x86-64, then repeat on ARM64 before
  claiming portable memory-ordering correctness.
- After the E2E test is useful, add focused property/fuzz tests for Mold state
  transitions, tracepoint schemas, record decoding, and malformed BPF objects.
- Preserve every discovered failure as a deterministic regression test.

Postponed: Broader Samurai testing

- Defer additional integration, end-to-end, workload, compatibility, and
  regression testing while the syscall presets and report semantics are still
  being completed.
- Keep the existing test suite passing as implementation work continues.
- Before a production-ready claim, test complete recordings and reports on
  representative file, process, and network workloads, including failures,
  process descendants, lane overflow, and shutdown draining.
